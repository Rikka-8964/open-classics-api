# open-classics-api

**面向学习者、教师与教育软件的中华经典诗文开放 JSON API —— 公版数据，零依赖，MIT 许可。**

[English](README.md) · [API 契约](http://localhost:8000/api/openapi.json) · MIT License

---

## 为什么做这个

古诗词是中国每个学生的必修内容，也是海外华裔与汉语学习者共同的课题。但这些材料是散的：躺在扫描的课本里、躺在程序读不了的 PDF 里，或者躺在为语言学家准备的大型语料库里——恰恰没有为"学习者"准备的那一层。

缺的是中间那层：**一个干净、机器可读、带免费 API 的小型语料库**。有了它，想做一个背诗 App、一个默写练习、一套 Anki 卡片或一份课堂测验的人，就不用自己爬取和清洗文本了。

这个项目就是那一层。范围刻意做窄，实现刻意做笨：一个 JSON 文件，一个小的 Python 服务，没有数据库，没有第三方依赖。

### 给谁用

- **学生**：想起半句诗，搜一下就能拿到全文和一句白话解释。
- **教师**：不用从十几个网站复制粘贴，就能生成默写卷或测验。
- **教育工具开发者**：拿到一个稳定、有文档、支持 CORS 的 JSON 接口，而不是一个随时会坏的爬虫。
- **汉语学习者**：需要的是原文加一句简注，不是一套考据。

### 不做什么

这不是研究语料库，不是全部中国文学的全文本档案，也不打算和大型学术数据集竞争。它是一个**面向学习的精选语料**：只收大家真正在学的作品，配上学习类应用需要的那点元数据。

## 语料内容

| | |
|---|---|
| 篇目 | 47 |
| 作者 | 21 |
| 朝代 | 唐、宋、五代、三国、先秦 |
| 体裁 | 五言绝句、七言绝句、五言律诗、七言律诗、词、铭、说、书、语录体 |
| 主题标签 | 66 个（思乡、边塞、隐逸、咏物……） |

所有作品均为**公有领域**。作者辞世均超过一百年，不对文本主张任何版权。编纂原则记录在 `data/works.json` 的 `meta.editorial_policy` 中：文本依中小学教材通行的标准版本，承认存在异文，欢迎通过 Pull Request 订正。

每条记录长这样：

```json
{
  "id": "tang-jingyesi",
  "title": "静夜思",
  "author": "李白",
  "dynasty": "唐",
  "genre": "五言绝句",
  "tags": ["思乡", "月", "夜晚"],
  "content": ["床前明月光，", "疑是地上霜。", "举头望明月，", "低头思故乡。"],
  "note": "以极浅白的语言写羁旅思乡：月光如霜，抬头低头之间，乡愁已满。"
}
```

`content` 是按诵读停顿切分的行数组，客户端不需要猜断句在哪。`note` 是写给学习者的一句话，不是写给专家的。

## 快速开始

不用安装、不用虚拟环境、不用 requirements。Python 3.10+ 加标准库就够。

```bash
git clone https://github.com/<your-username>/open-classics-api.git
cd open-classics-api
python app.py
```

打开 <http://localhost:8000> 是浏览界面，也可以直接调接口：

```bash
curl "http://localhost:8000/api/works?q=明月&limit=3"
curl "http://localhost:8000/api/works/tang-jingyesi"
curl "http://localhost:8000/api/random?tag=思乡"
```

换端口：`PORT=3000 python app.py`

跑测试：`python -m unittest discover -s tests -v`（24 项，覆盖检索排序、筛选、分页、确定性与 HTTP 层）。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/health` | 存活探针 |
| `GET` | `/api/stats` | 语料统计与服务指标 |
| `GET` | `/api/works` | 检索、筛选、排序、分页 |
| `GET` | `/api/works/{id}` | 按 id 取单篇 |
| `GET` | `/api/random` | 随机一篇，可加约束 |
| `GET` | `/api/authors` | 作者分布 |
| `GET` | `/api/tags` | 主题标签分布 |
| `GET` | `/api/dynasties` | 朝代分布 |
| `GET` | `/api/genres` | 体裁分布 |
| `GET` | `/api/facets` | 一次性返回全部维度 |
| `GET` | `/api/openapi.json` | OpenAPI 3.1 描述 |

`/api/works` 参数：`q`（空格分隔多词，按 AND 组合）、`author`、`dynasty`、`genre`、`tag`、`page`（默认 1）、`limit`（默认 20，上限 100）、`sort`（`relevance` / `title` / `author` / `dynasty`）。

排序权重是显式常量，写在 `classics/store.py` 顶部：篇名精确命中 1000、篇名部分命中 300、作者 200、标签精确 160、标签部分 120、正文 100、体裁与朝代 60、注解 40。某个词什么都没命中，该篇即被剔除；多词得分累加，同分按篇名排序。之所以不用打分库，是为了让排序行为可被审查、可被讨论。

限流：每客户端 60 秒 120 次，超出返回 429。

## 部署

服务从环境变量读取 `HOST` 与 `PORT`，绑定 `0.0.0.0`，在 VPS、容器或反向代理后都能原样运行：

```bash
PORT=8000 python app.py
```

因为没有任何第三方依赖，部署不需要构建步骤、锁文件和包管理器。

### 为什么它需要一台服务器

单纯一份 JSON 语料，其实可以当静态文件托管。但这个项目是一个**服务**，下面这些能力真的需要一个常驻进程：

- **服务端检索与排序**：相关度是按查询在整个语料上现算的，还包含多词 AND 匹配，静态托管做不到。
- **服务端筛选、排序与分页**：66 个标签、21 位作者、10 种体裁，客户端不必为了查一次就下载整个语料。
- **限流与用量统计**：这正是"可以免费把接口开放给公众而不被滥用"的前提。
- **稳定常驻的入口**：给那些不能依赖"学生笔记本醒着"的第三方教育应用用。

服务本身很轻：整个语料只有几 KB，所以 1 vCPU / 1 GB 的实例目前远超所需。这份余量本身就是目的——为语料和流量的增长留出空间，而不必重写。

## 路线图

语料是**种子**，不是完工的档案。计划中的工作，大致按顺序：

- [ ] 扩充到约 300 篇，覆盖义务教育阶段的完整篇目
- [ ] 为每个字加 `pinyin` 字段，服务第二语言学习者
- [ ] 加 `level` 字段，把篇目对应到小学 / 初中 / 高中
- [ ] 提供每篇的繁体版本
- [ ] 静态导出模式：为低带宽课堂生成完全离线的副本
- [ ] 可选 SQLite 后端，供超出内存存储规模的部署使用

欢迎就以上任何一项提交贡献，见 [CONTRIBUTING.md](CONTRIBUTING.md)。
